# TSG Lineup — Signal-Domain Reference Pattern Specification

**Document:** TSG-LINEUP-SPEC · **Version:** 1.0 · **Status:** Normative

---

## Abstract

This document specifies the signal-domain model, colorimetry, quantisation and
conformance requirements for the reference test patterns generated by TSG Lineup.
A reference pattern generator shall hold its truth in a **format-independent
signal master** expressed as exact fractions, and shall render every output — an
8-bit preview, a 10-bit SDI signal, or a high-dynamic-range encode — as a
faithful, deterministic quantisation of that single master. The waveform monitor
is thereby reduced to a *confirmation* of a known truth rather than a measurement
of a lossy derivative.

---

## 1. Scope

This specification defines:

- the normative **signal domain** in which patterns are authored (§4);
- the **colorimetry and quantisation** from that domain to each coded output
  (§5), with exact reference code values (§6);
- the **pattern-description schema** shared by all conforming renderers (§7);
- the **renderer conformance requirements**, including bit-exact determinism
  (§8);
- the treatment of **high dynamic range** (§9); and
- the **conformance methodology** by which a rendered signal is verified against
  this specification (§10).

It does not specify dynamic overlays (timecode, synchronisation aids, slates),
which carry no reference levels and are outside the conformance scope (§10).

## 3. Terms, definitions and conventions

**Signal fraction (`s`).** A normalised, display-referred, non-linear (OETF-
encoded) signal value per primary channel, defined such that

```
s = 0.0  → reference black          s = 1.0  → reference white
s < 0.0  → footroom (sub-black)      s > 1.0  → headroom (super-white)
```

A pattern authored as “75 %” denotes a signal fraction of `0.75`, **not** 75 % of
linear luminance.

**Narrow (studio) range.** The coded range in which reference black and white map
to the standard footroom/headroom-bearing code values (10-bit: 64 and 940).

**Full range.** The coded range in which black and white map to the extremes of
the coding word (8-bit: 0 and 255). Used for the sRGB preview only.

**Co-sited (left-sited) chroma.** In 4:2:2, the horizontal position at which the
single chroma pair for luma samples `(2n, 2n+1)` is located at the position of
the **even** sample `2n`.

**Conventions.** The key words **shall**, **shall not**, **should** and **may**
are to be interpreted as requirement levels. All arithmetic is specified on real
numbers; quantisation to integers is defined in §5.

## 4. The signal domain (normative)

The master **shall** express every colour as a signal fraction per primary
channel (§3), independent of any coded output format.

- Values **shall** be interpreted as non-linear R′G′B′. No transfer function is
  applied on the SDR path; transfer functions enter **only** where the pipeline
  passes through linear light (HDR encoding and cross-gamut conversion, §9).
- The master **shall** carry a colour-system tag identifying the primaries and
  the luma matrix. The default system is **ITU-R BT.709**.
- Geometry **shall** be resolution-independent, expressed as fractions of frame
  width and height, so that one master renders identically at any raster.

## 5. Colorimetry and quantisation (normative)

### 5.1 Luma and colour-difference matrix (BT.709, signal domain)

```
Y′ = 0.2126·R′ + 0.7152·G′ + 0.0722·B′
Cb = (B′ − Y′) / 1.8556          1.8556 = 2·(1 − 0.0722)
Cr = (R′ − Y′) / 1.5748          1.5748 = 2·(1 − 0.2126)
```

with `Y′ ∈ [0, 1]` nominal and `Cb, Cr ∈ [−0.5, +0.5]` nominal.

### 5.2 Quantisation to 10-bit narrow range (SMPTE ST 274 / ITU-R BT.709)

```
Y_code = round(64  + 876·Y′)     876 = 219 × 4    → black 64,  white 940
C_code = round(512 + 896·C)      896 = 224 × 4    → neutral 512, range [64, 960]
```

- Rounding **shall** be *round half away from zero*. The rounding convention is
  normative: a reference generator is bit-deterministic (§8).
- Active-picture codes **shall** be clamped to the valid range **[4, 1019]**.
  Code words `0x000–0x003` and `0x3FC–0x3FF` are reserved for the SAV/EAV timing
  reference sequences and **shall not** appear in active video.

### 5.3 Quantisation to 8-bit (preview)

```
Y_code = round(16  + 219·Y′)     → black 16,  white 235
C_code = round(128 + 224·C)      → neutral 128, range [16, 240]
```

clamped to **[1, 254]**. The preview is a legibility aid, not a reference; 8-bit
banding on gradients is inherent to this path and is accepted.

### 5.4 Chroma siting (normative)

4:2:2 carries one chroma pair per two luma samples. Chroma **shall** be
horizontally **co-sited** (§3): the chroma sample for the pair `(2n, 2n+1)`
belongs at the position of the even luma sample `2n`.

A conforming renderer **shall not** derive chroma by down-sampling rendered
pixels. It **shall** evaluate the ideal pattern analytically at the co-sited
position. There is consequently no down-sampling filter and no edge artefact:
the pattern is known exactly at every sample coordinate.

## 6. Reference code values (normative)

The following values are computed from the exact model of §5 and **shall** be
reproduced bit-for-bit by a conforming 10-bit renderer.

### 6.1 EBU 100/0/75/0 colour bars — 10-bit narrow (Y′ Cb Cr)

White bar 100 %; colour components 75 % / 0 % (per EBU Tech 3299).

| Bar     | Y′  | Cb  | Cr  |
|---------|-----|-----|-----|
| white   | 940 | 512 | 512 |
| yellow  | 674 | 176 | 543 |
| cyan    | 581 | 589 | 176 |
| green   | 534 | 253 | 207 |
| magenta | 251 | 771 | 817 |
| red     | 204 | 435 | 848 |
| blue    | 111 | 848 | 481 |
| black   |  64 | 512 | 512 |

### 6.2 Levels / PLUGE strip — 10-bit narrow (luma)

| Level                     | Y_code |
|---------------------------|--------|
| Sub-black (−5.5 %)        |   16   |
| Black (0 %)               |   64   |
| PLUGE −2 %                |   46   |
| PLUGE +2 %                |   82   |
| White (100 %)             |  940   |
| Super-white (+8.7 %)      | 1016   |
| Grey (75 %)               |  721   |

### 6.3 Ramp resolution

A 0 → 100 % grey ramp rendered from the exact master **shall** occupy the full
**877** distinct 10-bit luma codes across the 64–940 span. An 8-bit-authored
source yields only 220 codes — a fourfold loss of levels, visible as banding on a
10-bit display; such a source **shall not** be used as the reference.

## 7. Pattern-description schema

The master is language-neutral data, consumed identically by every conforming
renderer. Geometry is resolution-independent; levels are signal fractions (§4).

```jsonc
{
  "id": "ebu-lineup",
  "system": { "primaries": "BT709", "domain": "display-signal" },

  // Static reference layers, composited top-to-bottom.
  // Regions are [x, y, w, h] as fractions of the frame.
  "layers": [
    { "region": [0.0, 0.00, 1.0, 0.65], "fill": { "bars": "ebu75" } },
    { "region": [0.0, 0.65, 1.0, 0.05], "fill": { "strip": "levels" } },
    { "region": [0.0, 0.70, 1.0, 0.05], "fill": { "gradient": { "axis": "x", "from": 0.0, "to": 1.0 } } },
    { "region": [0.0, 0.75, 1.0, 0.25], "fill": { "solid": [0.75, 0.0, 0.0] } }
  ],

  "defs": {
    "bars": {
      "ebu75": [                                   // R′G′B′ fractions; white 100 %, colours 75 %
        [1.00,1.00,1.00],[0.75,0.75,0.00],[0.00,0.75,0.75],[0.00,0.75,0.00],
        [0.75,0.00,0.75],[0.75,0.00,0.00],[0.00,0.00,0.75]
      ]
    },
    "strip": {
      "levels": {
        "wedge":   [0.00, 0.20, 0.40, 0.60, 0.80, 1.00],
        "cluster": [-0.055, 0.00, -0.02, 0.02, 1.00, 1.087]   // SUB 0% −2% +2% 100% SUP
      }
    }
  },

  // One entry per target. Each output is a faithful encode of the same master.
  "outputs": [
    { "id": "sdi-hd",  "encode": { "matrix": "BT709", "range": "narrow", "bits": 10, "sub": "4:2:2-cosited", "container": "v210" } },
    { "id": "preview", "encode": { "space": "sRGB",    "range": "full",   "bits": 8 } },
    { "id": "sdi-hdr", "encode": { "system": "BT2100-PQ", "transform": "BT2408-sdr-in-hdr", "refWhiteNits": 203, "range": "narrow", "bits": 10 } }
  ]
}
```

Fill kinds are `solid`, `gradient`, `bars` and `strip`. Text labels are an
overlay concern, not a fill, and are outside the conformance scope (§10).

## 8. Renderer conformance requirements (normative)

Every conforming renderer consumes the **same** master plus a chosen output id;
the signal can therefore never diverge between preview and wire.

**8.1 Pipeline order.** For each output sample position `p`, a renderer **shall**:

1. resolve the layer and fill covering `p`;
2. evaluate the ideal signal `R′G′B′(p)` at floating-point precision — for
   chroma, at the co-sited position (§5.4), never by down-sampling;
3. transform to the output coding (apply the §5.1 matrix for Y′Cb′Cr′ targets,
   or pass R′G′B′ for RGB targets; for HDR, apply §9);
4. quantise per the output bit depth and range (§5), rounding half away from
   zero; and
5. clamp to the valid active range and pack into the container.

**8.2 Determinism.** Given an identical master and output id, a renderer **shall**
produce byte-identical output on every run and platform. No source of time,
randomness, locale or scheduling may influence a coded sample. Single-precision
floating point provides sufficient headroom for 10- and 12-bit targets.

## 9. High dynamic range

HDR is **not** the SDR bars re-encoded. Two distinct, separately standardised
operations are defined and **shall not** be conflated.

**9.1 SDR-in-HDR (ITU-R BT.2408).** A defined mapping of an SDR signal into an
HDR container: linearise the SDR signal (BT.1886 EOTF); scale so SDR reference
white (100 %) maps to HDR **reference white, 203 cd/m²**; convert BT.709 → BT.2020
primaries in linear light; apply the **PQ OETF (SMPTE ST 2084)**; apply the
Rec.2020 non-constant-luminance matrix; and quantise to 10-bit narrow range. Under
this mapping the 100 % white bar lands on luma code **≈ 572** (PQ is absolute:
203 cd/m² is ≈ 58 % of the PQ signal) and black on **64**.

**9.2 Native HDR patterns (ITU-R BT.2111).** HDR colour bars have their own
standardised values, which are **not** the SDR bars re-mapped. These **shall** be
authored as separate master files in the HDR system’s own terms. Exact HDR code
values are taken from the governing recommendation, never invented.

**9.3 HDR metadata.** Where a container carries out-of-band HDR signalling, the
mastering-display metadata (SMPTE ST 2086) and the transfer/colour-space
identification **shall** describe the encoded signal exactly (EOTF = PQ,
colour space = Rec.2020, primaries/white per BT.2100).

## 10. Conformance methodology

Conformance is established by rendering a master to a coded output, capturing that
output, and comparing each reference region against the value this specification
prescribes:

```
render(master, "sdi-hd") → capture → for each reference region:
    assert measured_code == encode10( signal_at(region) )
```

- **Flat regions, luma:** exact, 0 LSB.
- **Chroma at bar edges:** exact at the co-sited position — no averaging tolerance
  is admissible, because the ideal chroma there is known exactly (§5.4).
- The reference is the specification’s exact level (e.g. PLUGE −2 % ⇒ **46**),
  never a value derived from a lower-precision source.

Dynamic overlays are composited by each renderer’s own code, carry no reference
levels, and are outside this scope. Precision applies to the static reference
layer only.
